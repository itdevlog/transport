# Дизайн: веб-обёртка «Маршрут» (Екатеринбург)

- Дата: 2026-10-15
- Статус: утверждён, готов к планированию реализации
- Источник данных: транспортный портал `маршрут.екатеринбург.рф`
  (punycode `xn--80axnakf7a.xn--80acgfbsl1azdqr.xn--p1ai`)

## 1. Цель

Сделать лёгкую веб-обёртку над транспортным порталом Екатеринбурга, чтобы
быстро узнавать **когда ожидать транспорт** на нужной остановке — без карты и
без ожидания загрузки тяжелого SPA портала.

Ключевые сценарии:

1. Открыть сайт-обёртку и сразу видеть избранные остановки с живым прогнозом
   прибытия.
2. Пройти по меню: **каталог маршрутов → маршрут → остановки маршрута →
   прогноз прибытия** (сценарий «схемы маршрутов», который выбран основным).
3. Найти остановку по названию и посмотреть прогноз.
4. Добавить в избранное маршрут или остановку для быстрого доступа.

## 2. Границы

### В рамках
- Веб-сервис на Python 3 (только стандартная библиотека), разворачивается на
  Debian-сервере.
- Фронтенд: чистые HTML/CSS/JS, без сборки и без npm.
- Меню/экраны: Избранное (главная), Каталог маршрутов, Маршрут, Поиск
  остановок, Остановка (прогноз).
- Избранное: и маршруты, и остановки; сохраняется на диск (`favorites.json`).
- Живое авто-обновление прогноза на странице остановки.
- Кэширование запросов к порталу, аккуратная обработка ошибок.

### Вне рамок (YAGNI)
- Карта и геолокация.
- Экран «движение транспорта» с картой (координаты игнорируются).
- Авторизация, пользователи, многопользовательский режим.
- База данных (используется JSON-файл + память).
- Мобильное приложение, push/уведомления.
- Запись данных на портал (обращения, голосования) — только чтение.

## 3. API портала (справочник)

Единая точка входа: `POST https://<портал>/php/apiRequest.php?<cd>` с
JSON-телом. Транспорт — HTTPS; сертификат подписан российским УЦ, поэтому при
запросах проверка сертификата отключается.

### Формат запроса
```json
{
  "t": "<токен>",
  "ct": 26,
  "cd": "<команда>.php",
  "reg": 66002,
  "w": -1,
  "data": { "wuid": "<id клиента>", "...": "параметры команды" }
}
```

### Формат ответа
```json
{ "r": "ok" | "fail", "data": "…", "reason": "…", "message": "…" }
```
- `"r":"ok"` — успех, полезные данные в `data`.
- `"r":"fail"` — ошибка; `reason`/`message` содержат причину
  (напр. `"Некорректный токен"`, `"Отсутствует t"`).

### Команды, используемые обёрткой
| Команда | Параметры `data` | Назначение |
|---|---|---|
| `getRoutes.php` | — (только `wuid`) | каталог маршрутов |
| `getRouteById.php` | `id` (id маршрута) | маршрут: `subroutes[]` → `stations[]` |
| `getStations.php` | — | все остановки (для поиска) |
| `getStationForecasts.php` | `sid` (id остановки) | живые прибытия на остановку |

### Проверенные структуры данных

`getRoutes.php` → `data[]`:
`{ id, number, shortName, name, routeTypeId, fromStation, toStation, companyName, price }`

`getRouteById.php` (`data.id`) → `data`:
```
{ id, number, shortName, name, fromStation, toStation, type,
  companyName, price,
  subroutes: [
    { id, name, isMain, forwardDirection,
      points:   [ { lat, lng } ],
      stations: [ { id, name, description, lat, lng, direction } ] }
  ] }
```
Пример (маршрут 87): 2 направления — subroute 1555 «Академика Ландау»
(43 остановки, включает «Академия тенниса» id 5830), subroute 1554
«Горбольница № 7» (42 остановки).

`getStationForecasts.php` (`data.sid`) → `data[]`:
```
{ stationId, deviceCode, routeId, routeShortName, routeName, routeNumber,
  routeTypeId, subrouteId, lastStation, whereGo, arrivalTimeInSec, typeId }
```
- `arrivalTimeInSec` — секунды до прибытия (ключевое поле «когда ожидать»).
- `whereGo` — направление; `lastStation` — предыдущая остановка борта;
  `routeNumber`/`routeShortName` — номер маршрута; `deviceCode` — id борта.

`getStations.php` → `data[]`:
`{ id, name, description, adress, direction, lat, lng, shortname, tags }`
- `id` остановки из маршрута совпадает с `sid` в прогнозе.

### Виды транспорта (`routeTypeId`)
Для фильтра в каталоге: `1` — автобус, `2` — троллейбус, `3` — трамвай,
`4` — прочее/иное. Неизвестные типы показываются как «Другое».

## 4. Архитектура

```
/root/github/pi/
  server.py                     http.server: статика + JSON-API
  portal.py                     клиент портала (запросы, кэш, ошибки)
  config.json                   token, reg, wuid, host, port, TTL
  favorites.json                избранное
  static/
    index.html
    app.js
    style.css
  tests/
    test_portal.py
    test_server.py
  systemd/marshrut.service      unit для Debian
  README.md
```

Поток данных:
`Браузер → server.py (/api/*) → portal.py → портал (apiRequest.php)`.
Сервер — единственная точка, обращающаяся к порталу (обходит CORS и прячет
токен). Браузер работает только с нашим `/api/*`.

## 5. Модуль `portal.py`

Публичный интерфейс:
- `PortalClient(config)`:
  - `get_routes() -> list`
  - `get_route(route_id: int) -> dict`
  - `get_stations() -> list`
  - `get_forecasts(sid: int) -> list`
  - внутренний `_request(cmd, data) -> dict` — сборка тела, POST, таймаут,
    разбор ответа, выброс `PortalError` при `r":"fail"`/сети.
- `PortalError(reason, message)` — доменная ошибка.
- Кэш: `CachedValue` с TTL и защитой от параллельного дублирования запросов
  («single-flight»). TTL из конфига:
  - `routes`, `route`, `stations` — ~21600 сек (6 ч);
  - `forecasts` — ~10 сек.
- Отключение проверки SSL только для домена портала.
- Токен, `reg`, `wuid` — из `config.json`.

## 6. HTTP API обёртки (`server.py`)

| Метод | Путь | Параметры | Ответ |
|---|---|---|---|
| GET | `/api/routes` | `type?` (фильтр routeTypeId) | `{ routes: [ … ] }` |
| GET | `/api/route` | `id` | `{ route: { … } }` |
| GET | `/api/stations` | `q` (подстрока имени) | `{ stations: [ … ] }` |
| GET | `/api/forecast` | `sid` | `{ forecasts: [ … ] }` |
| GET | `/api/favorites` | — | `{ routes: [ … ], stops: [ … ] }` |
| POST | `/api/favorites` | `{ action: "add"\|"remove", kind: "route"\|"stop", id, name }` | обновлённое избранное |
| GET | `/*` | — | статические файлы из `static/` |

- Ответы — JSON, кодировка UTF-8.
- Ошибки: `{ error: { reason, message } }` + HTTP-код (400/502/500).
- `ThreadingHTTPServer`; порт из конфига (по умолчанию 8000).

## 7. Избранное

`favorites.json`:
```json
{
  "routes": [ { "id": 1554, "number": "87", "name": "Академика Ландау – Горбольница № 7" } ],
  "stops":  [ { "id": 5830, "name": "Академия тенниса" } ]
}
```
- Запись атомарная (временный файл + переименование).
- При добавлении сервер дополняет `name`, если он не передан.
- Дубликаты по `id` игнорируются.
- Файл можно править вручную.

## 8. Фронтенд

Роутинг по hash (без перезагрузки страницы):
- `#/` — **Избранное** (главная): сохранённые маршруты и остановки; у каждой
  избранной остановки сразу показывается живой прогноз.
- `#/routes` — **Каталог маршрутов**: фильтр по виду транспорта, поиск по
  номеру, ⭐ (добавить/убрать из избранного).
- `#/route/:id` — **Маршрут**: переключатель направлений (subroutes), список
  остановок; клик по остановке → `#/stop/:sid`; ⭐ на строке остановки.
- `#/stops` — **Поиск остановок**: поле поиска по названию (`/api/stations`),
  результаты → `#/stop/:sid`; ⭐.
- `#/stop/:sid` — **Остановка**: прогноз по **всем маршрутам** остановки,
  авто-обновление ~20 сек; ⭐.

Отображение прогноза (строка): номер маршрута · направление (`whereGo`) ·
«через N мин» (из `arrivalTimeInSec`) · ожидаемое время прибытия (текущее
время + N). Список отсортирован по возрастанию `arrivalTimeInSec`.

Поведение:
- Индикатор обновления и времени последнего запроса.
- При ошибке портала — баннер; если есть кэшированные данные, показываем их
  с пометкой «устарело», иначе — сообщение об ошибке.
- Адаптивная вёрстка (телефон/десктоп).

## 10. Обработка ошибок

- `PortalError` (сеть/таймаут/`r":"fail"`) → `/api/*` отдаёт 502 с
  `{ error: { … } }`; фронт показывает баннер.
- Ошибки конфигурации/файлов → 500 с понятным сообщением.
- Неизвестный путь → 404.
- Сервер не падает из-за ошибок портала (перехват на уровне хендлера).

## 12. Развёртывание (Debian)

- Запуск: `python3 server.py` (зависимостей нет).
- `systemd/marshrut.service`: `ExecStart=/usr/bin/python3 /opt/marshrut/server.py`,
  `Restart=on-failure`, `WorkingDirectory`.
- Опционально nginx как reverse-proxy на `127.0.0.1:8000`.
- `README.md`: установка, конфиг, systemd, обновление.
